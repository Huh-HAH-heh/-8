# Лабораторная работа №8: Проектирование БД со связью Один-ко-многим

**Выполнил:** Студент группы ИС-31
**Вариант:** №1 (Факультеты и Группы)

## 1. Схема данных и Предметная область
* **Родительская таблица:** `faculties` (Сущность "один" — Факультет)
* **Дочерняя таблица:** `groups_table` (Сущность "многие" — Академические группы)
* **Поле-связка:** `groups_table.faculty_id REFERENCES faculties(id)`

### Проектирование структуры таблиц
**Таблица `faculties` (Родительская):**
* `id` (INTEGER, PRIMARY KEY AUTOINCREMENT) — Уникальный номер
* `faculty_number` (TEXT, NOT NULL, UNIQUE) — Сокращенный номер/код факультета
* `name` (TEXT, NOT NULL) — Наименование факультета
* `dean` (TEXT, NOT NULL) — ФИО Декана

**Таблица `groups_table` (Дочерняя):**
* `id` (INTEGER, PRIMARY KEY AUTOINCREMENT) — Уникальный номер
* `group_number` (TEXT, NOT NULL, UNIQUE) — Номер академической группы (напр. ИС-31)
* `specialty_code` (TEXT, NOT NULL) — Код специальности (напр. 09.02.07)
* `faculty_id` (INTEGER, REFERENCES faculties(id)) — Ссылка на ID родительского факультета

## 2. Обоснование структуры проекта
* Исходный код изолирован в каталоге `src/`, данные хранятся отдельно в папке `data/`.
* Файл базы данных `.db` является динамическим артефактом сборки/выполнения программы. Его нельзя коммитить в общий репозиторий Git, поэтому он добавлен в `.gitignore`.
* Сама папка `data/` сохраняется в Git с помощью пустого файла-заглушки `.gitkeep`, чтобы программа не падала у других разработчиков при попытке обратиться к несуществующей директории.
